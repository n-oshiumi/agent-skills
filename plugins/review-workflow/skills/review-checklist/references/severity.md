# 重大度定義(全リポ共通)

| 等級 | 意味 | 対応 |
| --- | --- | --- |
| **P0** | 事故級: 不変条件違反・データ破損/消失・秘密漏洩・認可バイパス/テナント越境・二重課金/二重販売・実行時クラッシュ | 必ず修正。残して完了しない |
| **P1** | 仕様バグ: 仕様乖離・エラーハンドリング欠如・冪等性欠如・未検証の重要ロジック・境界の型安全性・セキュリティ弱点 | 必ず修正 |
| **P2** | 品質: 可読性・軽微リファクタ・過剰フェッチ・軽微 UX | 既定は学習記録のみ。完了条件に含めるかはリポ側が決める |
| **P3** | 好み・将来の改善提案 | 報告のみ |

## ルール

- **昇格**: 既定の等級は目安。実影響が大きければ上げる(例: 境界の型逃げが決済・状態遷移に触るなら P1 以上。認可の甘い旧ルートが残るデッドコードは P1)。
- **資格要件**: P0/P1 は「前提 → 入力 → 結果」の失敗シナリオと `ファイル:行` の引用を必ず添える。**P0 は失敗するテストとして書けるものに限る**。書けない指摘は P2 以下(または質問)に降格する。
- **スコープ**: 今回の差分に起因する指摘だけを等級付けする。差分が触っていない既存の欠陥は「既存の逸脱」として別掲し、ブロック理由にしない。
- **既存表記との対応**: Tier1 ≈ P0/P1、Tier2 ≈ P1/P2、Tier3 ≈ P2/P3。「必須」≈ P0/P1、「推奨」≈ P2。
