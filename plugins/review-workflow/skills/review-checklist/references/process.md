# process — レビューの作法(誰がレビューしても同じ品質にする)

## 証拠
- 指摘(FAIL)には実際に読んだコードの引用と `ファイル:行` を添え、検出コマンドの結果を根拠にする。推測で FAIL にしない。PASS にも確認方法を 1 行書く
- FAIL 判定後、該当ファイルを再 Read して引用と行番号を自己検証する。確認できなければ取り下げるか「低確信」と明記する(幻覚指摘対策)
- 重大な指摘は修正前に自分で Read して実在確認する
- 正本ドキュメントの記述は実装の証拠にならない。本番の実物・実行結果で確認する

## スコープ
- 今回の差分に起因する指摘のみ。差分が触れていない既存コードの違反は「既存の逸脱」として別掲し、ブロック理由にしない(対象を広げると自己増殖ループになる)
- diff だけ読まず、変更ファイル全文と呼び出し元を読む(大きいファイルは変更関数+呼び出し元)
- 同型の既存コードが同じ書き方で稼働しているなら仕様の可能性が高い。既知仕様と照合し、それでも残る懸念のみ質問(P3)として出す
- レビュー前に過去教訓(review-learnings / knowledge)と規約を検索し、同じミスの再発をチェック項目に上乗せする

## 反証
- P0/P1 は「前提 → 入力 → 結果」の失敗シナリオを書けること。書けなければ P2 以下に降格する(→ severity.md)
- 「指摘ゼロ」は再走査する。ただしでっち上げ禁止。終了条件を「指摘ゼロ」にしない(adversarial reviewer は必ず何かを見つける)
- 逆方向チェック(diff に現れないものを疑う): 変更したシンボル名で全体 grep して呼び出し元の追従 / API を変えたら相手側(クライアント・型)を読む / 削除の残骸 / 同型の未修正箇所 / ドキュメント同期

## 出力
- 指摘 1 件の必須フィールド: 等級 / 位置+引用 / 事象 1 文 / 失敗シナリオ / 反証の試行 / 修正案。「概ね良い」で終わらせない
- 判定(P0/P1 の有無)を固定フォーマットで明示し、実施した確認と実施できなかった確認・その理由を分けて書く
- 完了報告の対象が作業ツリーと一致しているか(unstaged / untracked を見る)。「直した」と書く前に編集が当たったことを現物で確かめる

## 有界にする
- 停止条件(何をブロッカーとするか)を先に宣言する。2 周で P0/P1 が閉じないなら個別修正を止め、設計と不変条件を先に書き出す
- 不採用にした指摘は「指摘 → 理由」の台帳にして渡し、論拠自体に反論できるときだけ再提起させる
- 指摘が「前ラウンドの修正が作った欠陥」ばかりになったら設計を疑う。判断を仰ぐときは残指摘数でなく「base と比べて良くなっているか」で

## 学びの還流
- 再発し得る指摘は学習記録へ。観点が一般的なら該当 references の `## 候補(レビューで発見)` に 1 行追記する(実例・経緯はノートに書き、チェックリストからはリンク)
- 観点を足す前に「テスト・lint・CI で機械化できないか」を検討し、機械化できたら観点を削除する。候補は定期的に「昇格 / 機械化 / 破棄」に倒し、空に戻す
- 一過性の作業リストは完了時にステータスを付け、恒久教訓を正本へ昇格させてから閉じる
- 実装前にもチェックリストを引く(指摘されてから読むのは 1 往復無駄)

## git・マージ(CLAUDE.md の運用ルールに加えて)
- ブランチを触るコマンドの直前に毎回 `git branch --show-current` と `git status` を読む(共有作業ツリーでは HEAD が別セッションに動かされる)
- コミットは触ったパスを明示する(`git add -A` 禁止)。`git show --stat HEAD` で「入ってはいけないもの」と「入るはずのもの」の両方を照合する
- 他ブランチの確認に作業ツリーへ書き込むコマンドを使わない(`git show <ref>:<path>` 等の読み取りで)。無人ジョブの実行中にそのジョブが使う作業ツリーのブランチを切り替えない
- シークレット混入検査は三点差分の追加行に限定する(二点差分は他人の削除行が混じる)。誤検知は「自分のではない」で流さず検査の掛け方を直す
- 衝突解決で衝突ブロックの外を書き換えない。解決後に行数を比べる
- マージ後のブランチ削除・base 反映はツールのメッセージでなく実体(`git branch --list` / `git merge-base --is-ancestor`)で確認する
- issue は受け入れ基準と突き合わせて完全完了なら close、一部なら close せず残りをコメント。`Closes #n` は書く時点で判定し、残りがあれば `Refs #n`
- 生成物・スクショ・scratchpad のファイルをコミットしない
