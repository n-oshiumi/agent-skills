# infra — IaC・CI/CD・コンテナ・環境変数・デプロイ・無人ジョブ

## 秘密・権限
- [P0] 秘密をコミット・ハードコード・ログ出力しない。秘密を設定する CLI で値を引数に書かない(履歴・プロセス一覧・名前欄に残る)。設定後は一覧を読み返す
- [P0] IAM・セキュリティグループ・DB ロールは最小権限。権限スコープはコードが実際に叩く API 面から都度導出する
- [P0] 本番システムへの書き込み・デプロイはユーザーの明示指示があるときだけ。本番 CLI はプロジェクト/アカウントを ID で明示・照合する(名前で照合しない)
- [P0] 資格情報の環境・モードの取り違え(本番に test 鍵など)を、使う直前に fail-closed で照合する
- [P1] CI で secret を付与する step が、PR で変更可能なコードを実行していないか
- [P1] 無人エージェントの権限は宣言でなく実測で確認する。第三者が内容を決められる文字列を渡すなら隔離起動し、出口にも fail-closed の検査を置く

## 環境変数・設定
- [P1] 環境変数を新しく参照するコードを足したら、それを渡す全実行環境(ローカル雛形・CI・本番の各ワークロード)に値が供給されるか確認する(未設定で fail-closed する設計は入れ忘れで全停止する)
- [P1] 「起動時 fail-fast」を謳うガードが実際に起動経路へ配線されている。fail-closed ガードを足したら雛形どおりのローカル環境でも通るか確かめる
- [P1] 環境差分(URL・接続先)は環境変数で吸収する。本番のログレベル・secure cookie・デバッグ設定を後退させていない
- [P1] クライアントに出してよい値だけ公開用プレフィックスを付ける。サーバ専用値に誤って付けない
- [P1] import した外部モジュールが実行される全環境の依存宣言に明示されているか(暗黙の推移依存は環境差で本番ロード時に落ちる)

## デプロイ・IaC
- [P0] IaC apply の前に plan 要約(add/change/destroy)を読む。部分適用を全体の安全性の根拠にしない。同じ環境に apply する他セッションを確認する。削除保護は IaC 側と API 側で別物
- [P0] スキーマ変更を伴うデプロイは migration → コード配備 → 設定値の順。設定値は即反映されるので防御コードを含む版が本番に居ることを確認してから入れる
- [P1] 配備順は散文でなくそのまま流せるコード塊で残す。デプロイは「依頼された変更」でなく「作業ツリー全体」を出荷することを意識し、終了時に「本番 = base = 作業ツリー」を確かめる
- [P1] 外部サービス側の設定が前提の変更は、設定を先に完了 → 照合を本番相当で流す → デプロイの順を守る。外部システムの状態(webhook 登録・審査・secret)はライブのツールで実確認し、docs の「実装済み」を根拠にしない
- [P1] 外部サービスへ届いて初めて意味を持つ成果物(sitemap・計測タグ・webhook 登録)は受け手側に問い合わせて存在確認する(未登録は 200 のまま沈黙する)。計測タグは「送信が通った」を実ブラウザで確認し、CSP の allowlist は実測で決める
- [P1] 「ビルド・テストが緑」は配信物が正しいことを保証しない。ビルド成果物とマニフェスト/配信先の実体を突合するゲートを持つ。配信成果物のファイル名に空白を入れない
- [P1] 外部依存未設定のフェイルソフトは「何が動かないか」と解除タスクを配備報告に明記する
- [P2] エッジ・CDN・WAF の反映は時間差がある。キャッシュ回避で同じ結果が続くまで確認する。クローラ・ボットの許可は送客の実測とコストで裏づける
- [P2] 依存パッケージへのパッチは実際に実行されるファイルを特定し、外れたことを品質ゲートが検出できる形にする。バージョンを上げたらランタイム対応表も更新する

## コンテナ・ホスト
- [P0] DB・管理系ポートをループバックに限定し、既定パスワードを消し、接続ログを取る。本番由来の個人情報を開発構成へ入れない
- [P1] アプリのログ出力先がホスティングのログ回収経路と一致し、ファイル出力ならローテーションと容量上限がある。マスキングは構造化データの段階でキー名一致させ、出力チャンネルを変えても効く
- [P1] ヘルスチェックは unhealthy を消費する主体(再起動・通知)が定義され、生存証跡が「正しく動いている」を示す
- [P1] 信頼プロキシ範囲(real IP / forwarded ヘッダ)を実際に到達しうる範囲に絞る。コンテナ停止が graceful で、停止猶予が許容リクエスト長と各プロセスの猶予の合計を上回る
- [P1] 同一チェックアウトに複数の compose ファイルを置くならプロジェクト名を明示する。同一イメージを複数ロールで起動する構成で共有ボリュームへの初期化を特定ロール限定にする
- [P1] 本番イメージをビルドする CI があり、ビルド除外設定が開発中にだけ生成されるファイルを除外している
- [P1] ローカル/エミュレータから外部サービス(分析基盤・プッシュ・チャット)へ書く処理にローカル判定ガードを付ける。シードデータに実トークンを入れない
- [P1] 破壊的操作(TRUNCATE/DROP/全消去)の直前に接続先を実際に問い合わせる。別環境を模擬する検証でクラスタ単位の操作(ロール変更)を流さない

## 無人ジョブ・CLI
- [P1] 失敗通知はラッパー側の責務(殺された子は通知できない)。子にも予算を持たせ、成果物は必ず出す。fail-soft で握りつぶす分岐は理由を残す
- [P1] 終了コードは「検出した」「検査できなかった」「クラッシュ」を分ける。引数は厳格に解釈する(未知フラグ・値なしは副作用の前に非ゼロ終了)
- [P1] 送信・投稿系には dry-run を用意し、本番と同じ経路を通して最後の送信だけ止める。dry-run の失敗分岐の終了コード・通知もモードを見る
- [P1] 対象日を起動時刻から導かない(取りこぼし追走)。期間キーで処理単位を作るジョブは「未完了の単位」を期間より先に探す
- [P1] 上限つき逐次処理は使う順に並べ、打ち切りで何が欠けたかを出力する。定期レポートには報告対象そのものが動いていたか(計画 vs 実績)を入れ、累計を増分として読ませない
- [P1] 生成テキストをシェルコマンドに埋め込ませない(stdin 経由)。無人実行するラッパーは stdin を明示的に切り、同期の外部呼び出しにタイムアウトを付ける
- [P1] 「対策」として書いたツールは実行経路(定期ジョブ・ゲート・通知)へ繋いで初めて対策。チャネル・機能を終了するとき、それを見ている無人ジョブ・トークンも一緒に畳む
- [P1] リポ外オーケストレータが依存する呼び出し契約(script 名・フラグ・入力形式)は実起動で 1 周する。ジョブの起動レイヤを変えたら実行系がどれに解決されるか実際に叩く
