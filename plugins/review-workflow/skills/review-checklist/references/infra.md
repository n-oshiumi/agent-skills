# infra — IaC・CI/CD・コンテナ・環境変数・デプロイ・無人ジョブ

## 秘密・権限
- [P0] 秘密をコミット・ハードコード・ログ出力しない。アクセスログにヘッダを丸ごと出さない(独自の認証ヘッダは伏せられない)。秘密を設定する CLI で値を引数に書かず(履歴・名前欄に残る)、設定後は一覧を読み返す
- [P0] IAM・セキュリティグループ・DB ロールは最小権限。スコープはコードが叩く API 面から導出する。ビルド・デプロイの実行主体(既定のサービスアカウント)も含め、履歴で実測する
- [P0] 条件付き権限で名前を絞るなら、評価される名前の形式と list/create の評価対象(作成前の名前)を確かめ、list/create は別ロールにする。旧来の広い付与は「新付与 → 旧付与削除」の 2 段で外す
- [P1] 権限の静的検査は許可リストで書く。ロール名に加えリソース型(上位スコープ・authoritative な binding)・値がリテラルか・ツールが読む全ファイル形式まで見る
- [P0] 本番 CLI はプロジェクト/アカウントを ID で明示・照合する(本番への書き込み・デプロイは明示指示があるときだけ)
- [P0] 資格情報の環境・モードの取り違え(本番に test 鍵)を使う直前に fail-closed で照合する
- [P1] secret を付与する CI step が PR で変更できるコードを実行しないか。CI からクラウドへの鍵なし認証はリポジトリ・ブランチに加えワークフローのファイルとイベントでも絞る(別ワークフロー・pull_request_target も通る)
- [P1] 無人エージェントの権限は実測する。第三者の文字列を渡すなら隔離起動し、出口にも fail-closed の検査を置く。定期実行の runner はアカウント(設定ディレクトリ)と Keychain 用の USER を固定して既存 runner と突き合わせ、解決できなければ旧値の既定へ落とさず止める

## 環境変数・設定
- [P1] 新しく参照する環境変数は全実行環境(ローカル雛形・CI・本番の各ワークロード)に値が渡るか確かめる。fail-closed・fail-fast のガードは起動経路へ配線し、雛形どおりのローカルでも通るか見る
- [P1] 本番のログレベル・secure cookie・デバッグ設定を後退させない
- [P1] 人のアカウントを付け替えるなら、プロジェクト IAM に加え IaC 変数の既定値(通知先)・リソース単位の binding・権限照合スクリプトの定数まで洗う
- [P1] 外部モジュールは全実行環境の依存宣言に明示する。lockfile はデプロイ先と同じ版のパッケージマネージャ・ランタイム(lock 側で固定)で解決し clean install を通す。乗り換えたら旧マネージャ専用の設定(overrides 等)が効くか、lockfile を依存グラフ(脆弱性通知)が読めるか見る
- [P1] 公開用プレフィックスはクライアントに出してよい値だけに付ける。静的生成のページで実行時の環境変数を読まない(ビルド環境の値が焼き込まれる)。実行時の値を出すページは動的描画を明示してビルド出力で確かめる
- [P1] 脆弱性の上げ先は audit 系だけで決めず配布元のアドバイザリを上げ先の版で引き直す(集約 DB は公開直後に未反映)。推移的依存は親の更新で外れなければ overrides で上げ親の機能を動かす。修正版が無ければ成果物に入るか・攻撃者が入力を握れるかで判断し理由を残す

## デプロイ・IaC
- [P0] IaC apply の前に plan 要約(add/change/destroy)を読み、本番に自動承認を付けない。同じ環境へ apply する他セッションを見る。state が 1 つなら base へ rebase して plan し、apply と同時に main へ入れる(古い base だと main のリソースが削除の plan になる)。削除保護は IaC 側と API 側で別物。親を付け直すなら子の state も付け直し、plan に destroy・replace が無いことを apply の条件に
- [P1] スナップショット・レプリカから作るリソースは、継承される属性(暗号化・ストレージ種別)を設定にも明示する(未指定だと以後の update が replace に倒れる)
- [P0] 本番へ出すコマンドは HEAD でなく作業ツリーを出す。直前に clean か確かめ、終了時に「本番 = base = 作業ツリー」と配信先の実体を突合する。差分をまとめて出すなら本番の版..main の未デプロイコミットを列挙し、同梱してよいか・要る設定が本番にあるか見る(他人の未公開機能まで出る)
- [P0] スキーマ変更を伴うデプロイは migration → コード配備 → 設定値の順。配備順はそのまま流せるコード塊で残す
- [P1] 依存のメジャー更新は配布先の全 OS で起動経路の E2E を回してから出す(手元の OS だけ通る)
- [P1] 外部の設定が前提の変更は、設定 → 本番相当で照合 → デプロイの順。外部の状態(webhook 登録・審査・secret)と外部向け成果物(sitemap・計測タグ)は docs でなく受け手側・実ブラウザで確かめる。未設定で出すなら動かないものと解除タスクを配備報告に書く
- [P1] デプロイ前後のメモリ・レイテンシはリビジョン単位で比べる(直後は旧リビジョンが混ざる)
- [P2] エッジ・CDN・WAF の反映は時間差がある。追加はキャッシュ回避で、削除・差し替えは利用者と同じ URL(クエリなし)で確かめる
- [P2] 依存へのパッチは実行されるファイルを特定し、外れたらゲートが検出する形に
- [P2] 上書きで版が増える外部ストア(秘密管理等)は課金単位を確かめ、古い版を書き込み経路で後始末する

## コンテナ・ホスト
- [P0] DB・管理系ポートをループバックに限定し、既定パスワードを消す(IaC で作るマネージド DB も root パスワードを指定する。省くと無パスワードで残る)。本番由来の個人情報を開発構成へ入れない
- [P1] ログ出力先がホスティングの回収経路と一致し、ファイルならローテーションと上限がある。マスキングは構造化データの段階でキー名一致で
- [P1] ヘルスチェックの unhealthy を消費する主体(再起動・通知)がある。信頼プロキシは到達しうる範囲に絞る。停止猶予は許容リクエスト長より長く
- [P1] 同一チェックアウトに複数の compose ファイルを置くならプロジェクト名を明示する。共有ボリュームの初期化は特定ロール限定に
- [P1] ビルド・送信の除外は VCS の除外と別物。先頭 `/` の無いパターンは全階層に一致する。送信対象を一覧で確かめる
- [P1] エントリを共有するサーバレスはトップレベル import が全関数の起動時メモリに乗る。重い SDK は使う関数内で遅延読み込みし、テストで固定する
- [P1] ローカル/エミュレータから外部へ書く処理にローカル判定ガードを付け、破壊的操作(TRUNCATE/DROP)の直前に接続先を問い合わせる

## 無人ジョブ・CLI
- [P1] 失敗通知はラッパーの責務(殺された子は通知できない)。子にも予算を持たせ、fail-soft で握りつぶす分岐は理由を残す
- [P0] 監視・ゲートは判定器が生きているか(条件の指標が非推奨になっていないか)を先に疑う。定期ジョブは「exit 0」でなく成果物が読む側に届いた最後の時刻で確かめる
- [P1] 終了コードは「検出」「検査不能」「クラッシュ」を分け、一部失敗も非ゼロで返す(CI・cron は終了コードしか見ない)。手順書の合否も「0 以外」で判定。未知フラグは副作用の前に非ゼロ終了する
- [P1] 検査スクリプトは見逃しを止める側に倒す(`pipefail` 下の `find | grep -q` は SIGPIPE で偽になる。`grep` の 2 を「一致なし」にしない)。`.sh` は LF に固定し、変数直後にマルチバイト文字が続くなら `${var}`
- [P1] 送信・投稿系には本番と同じ経路で最後の送信だけ止める dry-run を置く。失敗分岐の終了コード・通知もモードを見る
- [P1] 対象日・予定を起動時刻から導かない(起動遅延で飛ばす。取りこぼしは追走)。「未完了の単位」を期間より先に探す
- [P1] 上限つき逐次処理は使う順に並べ、打ち切りで欠けたものを出力する。定期レポートには報告対象が動いていたか(計画 vs 実績)を入れる
- [P1] 生成テキストをシェルコマンドに埋め込ませない(stdin 経由)。ラッパーは stdin を切り、同期の外部呼び出しにタイムアウトを付ける
- [P1] 「対策」のツールは実行経路(定期ジョブ・ゲート・通知)へ繋ぎ、リポ外から呼ばれる契約(script 名・フラグ)は実起動で 1 周させ出力を読むまで対策でない。起動レイヤを変えたら解決先を叩く。機能を終えるなら無人ジョブ・トークンも畳む

## 候補(レビューで発見)
- 本番を手元に写す検査(webshell・改ざん)は、手元のウイルス対策が写した直後に消しうるので転送元と再照合する。露出検査(`/.env` 等)は本文を取らず状態コードとヘッダーで判定する(秘密を持ち出さない)
- 侵害されうる側で集めた一覧は構造化(JSON / NUL 区切り)して受ける。行区切りだと改行・CR 入りのファイル名で結果を書き換えられる
- 監視の不在判定は系列ごとに評価される。ラベル違いで系列が分かれる指標は、ジョブ等の単位で合算してから判定する(片方が途切れただけで鳴る)(clinic-dashboard 2026-10-27)
- 動作中の bash スクリプトを書き換えない(bash は実行しながら逐次読むので、走っている回が途中から別の行を実行して壊れる)。定期ジョブのランナーは止めてから直すか、新しいファイルに書いて mv で差し替える(cheers-hp-service 2026-11-05)
