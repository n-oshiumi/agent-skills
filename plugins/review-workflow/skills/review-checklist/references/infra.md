# infra — IaC・CI/CD・コンテナ・環境変数・デプロイ・無人ジョブ

## 秘密・権限
- [P0] 秘密をコミット・ハードコード・ログ出力しない。アクセスログにリクエストヘッダを丸ごと出さない(既定で伏せるのは Authorization・Cookie だけで独自の認証ヘッダは平文で残る)。秘密を設定する CLI で値を引数に書かない(履歴・名前欄に残る)。設定後は一覧を読み返す
- [P0] IAM・セキュリティグループ・DB ロールは最小権限。スコープはコードが実際に叩く API 面から導出する
- [P0] 条件付き権限で名前を絞るなら、評価される名前の形式と list/create の評価対象(作成前の名前)を確かめる。list/create は別ロールにし、旧来の広い付与は「新付与 → 旧付与削除」の 2 段で外す
- [P1] 権限の静的検査は許可リストで書く。ロール名だけでなくリソース型(上位スコープ・authoritative な binding)・値がリテラルか・ツールが読む全ファイル形式まで見る
- [P0] 本番への書き込み・デプロイはユーザーの明示指示があるときだけ。本番 CLI はプロジェクト/アカウントを ID で明示・照合する
- [P0] 資格情報の環境・モードの取り違え(本番に test 鍵)を、使う直前に fail-closed で照合する
- [P1] CI で secret を付与する step が、PR で変更可能なコードを実行していないか。CI からクラウドへの鍵なし認証はリポジトリ・ブランチに加えワークフローのファイルとイベントでも絞る(同じブランチの別ワークフロー・pull_request_target も通る)
- [P1] 無人エージェントの権限は実測で確認する。第三者が決める文字列を渡すなら隔離起動し、出口にも fail-closed の検査を置く

## 環境変数・設定
- [P1] 環境変数を新しく参照したら、全実行環境(ローカル雛形・CI・本番の各ワークロード)に値が供給されるか確認する。fail-closed ガードは雛形どおりのローカルでも通るか確かめる
- [P1] 「起動時 fail-fast」のガードが起動経路へ配線されている。本番のログレベル・secure cookie・デバッグ設定を後退させない
- [P1] クライアントに出してよい値だけ公開用プレフィックスを付ける
- [P1] 外部モジュールは実行される全環境の依存宣言に明示する。lockfile はデプロイ先と同じ版のパッケージマネージャ・同じランタイム版(lock 側で固定)で解決し、clean install が通るか確かめる
- [P1] ビルド時に静的生成されるページで実行時の環境変数を読まない(ビルド環境の値が本番に焼き込まれる)。実行時の値を出すページは動的描画を明示し、ビルド出力で確かめる
- [P1] 脆弱性の上げ先は Dependabot / audit だけで決めず配布元のアドバイザリを上げ先の版で引き直す(集約 DB は公開直後に未反映)。推移的依存は親の更新で外れなければ overrides で上げ親の機能を動かす。修正版が無いものは成果物に入るか・入力を攻撃者が制御できるかで判断し理由を残して却下する

## デプロイ・IaC
- [P0] IaC apply の前に plan 要約(add/change/destroy)を読み、本番に自動承認を付けない。同じ環境に apply する他セッションを確認する。state が 1 つなら apply と同時に main へ入れる(長命ブランチからの apply 後、main からの apply が削除の plan になる)。削除保護は IaC 側と API 側で別物
- [P1] スナップショット・レプリカから作るリソースは、継承される属性(暗号化・ストレージ種別)を設定側にも明示する(未指定は 2 回目以降の update が replace に倒れる)
- [P0] 本番へ出すコマンドは HEAD でなく作業ツリーを出す。実行直前に clean か確かめ、終了時に「本番 = base = 作業ツリー」を確かめる
- [P0] スキーマ変更を伴うデプロイは migration → コード配備 → 設定値の順。配備順はそのまま流せるコード塊で残す
- [P1] 外部サービス側の設定が前提の変更は、設定 → 本番相当で照合 → デプロイの順。外部の状態(webhook 登録・審査・secret)と外部へ届いて意味を持つ成果物(sitemap・計測タグ)は docs の「実装済み」でなく受け手側・実ブラウザで確かめる。CSP の allowlist は実測で決める
- [P1] 「ビルド・テストが緑」は配信物の正しさを保証しない。成果物と配信先の実体を突合するゲートを持つ
- [P1] 外部依存未設定のフェイルソフトは「何が動かないか」と解除タスクを配備報告に明記する
- [P1] デプロイ前後のメモリ・レイテンシはリビジョン単位で比べる(直後の窓に旧リビジョンが混ざる)
- [P2] エッジ・CDN・WAF の反映は時間差がある。追加の反映はキャッシュ回避で、削除・差し替えの反映はクエリを付けない利用者と同じ URL で確かめる(クエリ付きは旧版の残存を見逃す。パージで消えないキャッシュもある)
- [P2] 依存へのパッチは実行されるファイルを特定し、外れたことをゲートが検出できる形にする
- [P2] 上書きで版が増える外部ストア(秘密管理等)は課金単位を確かめ、今回足した版より古いものを書き込み経路で後始末する

## コンテナ・ホスト
- [P0] DB・管理系ポートをループバックに限定し、既定パスワードを消す(マネージド DB を IaC で作るときも root のパスワードを指定する。省くと無パスワードの root が残る)。本番由来の個人情報を開発構成へ入れない
- [P1] ログ出力先がホスティングのログ回収経路と一致し、ファイルならローテーションと上限がある。マスキングは構造化データの段階でキー名一致させる
- [P1] ヘルスチェックは unhealthy を消費する主体(再起動・通知)が定義されている。信頼プロキシ範囲を実際に到達しうる範囲に絞る。停止猶予が許容リクエスト長を上回る
- [P1] 同一チェックアウトに複数の compose ファイルを置くならプロジェクト名を明示する。共有ボリュームへの初期化は特定ロール限定にする
- [P1] ビルド・送信の除外は VCS の除外と別物。先頭 `/` の無いパターンは全階層に一致する。実際の送信対象を一覧で確かめる
- [P1] エントリを共有するサーバレスでは、トップレベル import の依存が全関数の起動時メモリに乗る。重い SDK は使う関数内で遅延読み込みし、テストで固定する
- [P1] ローカル/エミュレータから外部サービスへ書く処理にローカル判定ガードを付ける。破壊的操作(TRUNCATE/DROP)の直前に接続先を実際に問い合わせる

## 無人ジョブ・CLI
- [P1] 失敗通知はラッパー側の責務(殺された子は通知できない)。子にも予算を持たせ、fail-soft で握りつぶす分岐は理由を残す
- [P0] 監視・ゲートは判定器が生きているかを先に疑い、新しい監視は投入直後に手で走らせ出力を読む。定期ジョブは「exit 0」でなく、成果物が読む側に届いた最後の時刻で確認する
- [P1] 終了コードは「検出した」「検査できなかった」「クラッシュ」を分け、一部失敗も非ゼロで返す(CI・外部 cron は終了コードしか見ない)。手順書の合否も「exit 1 なら」でなく「0 以外なら」で書く。引数は厳格に解釈する(未知フラグは副作用の前に非ゼロ終了)
- [P1] 検査スクリプトは見逃しを止める側に倒す(`pipefail` 下の `find | grep -q` は SIGPIPE で偽になる。`grep` の終了コード 2 を「一致なし」にしない)。`.sh` は LF に固定し、変数直後にマルチバイト文字が続くなら `${var}`
- [P1] 送信・投稿系には本番と同じ経路で最後の送信だけ止める dry-run を用意する。失敗分岐の終了コード・通知もモードを見る
- [P1] 対象日・実行する予定を起動時刻から導かない(起動遅延で予定を飛ばす。取りこぼしは追走)。「未完了の単位」を期間より先に探す
- [P1] 上限つき逐次処理は使う順に並べ、打ち切りで何が欠けたかを出力する。定期レポートには報告対象が動いていたか(計画 vs 実績)を入れる
- [P1] 生成テキストをシェルコマンドに埋め込ませない(stdin 経由)。ラッパーは stdin を切り、同期の外部呼び出しにタイムアウトを付ける
- [P1] 定期実行から AI CLI を呼ぶ runner は、アカウント(設定ディレクトリ)と Keychain 用の USER を明示して固定し、既存 runner と突き合わせる
- [P1] 「対策」のツールは実行経路(定期ジョブ・ゲート・通知)へ繋ぎ、リポ外から呼ばれる契約(script 名・フラグ)は実起動で 1 周して初めて対策。起動レイヤを変えたら解決先を叩く。機能を終えるときは見ている無人ジョブ・トークンも畳む

## 候補(レビューで発見)
- 本番を手元に写す検査(webshell・改ざん)は手元のウイルス対策が写した直後に消しうる。転送元と再照合し、手元から消えたものを検知とする。露出検査(`/.env` 等)は本文を取得せず状態コードとヘッダーで判定する(露出していれば秘密を手元へ持ち出す)
- 侵害されうる側で集めた一覧を行・区切り文字で受けると、ファイル名に改行・CR を埋めて結果を書き換えられる。構造化(JSON / NUL 区切り)して受け、区切りには実行ごとの乱数を入れる
- IaC で親リソースを別の実体へ付け直す手順(復旧・移設)は、親を参照する子リソースの state も同時に付け直し、plan に destroy・replace が無いことを apply の条件にする(親だけ import すると子の削除・再作成が計画される。削除保護は親にしか効かない)(fukuro-automations 2026-10-25)
- マネージド DB の復旧手順がバックアップを前提にするなら、インスタンス削除でバックアップが消えない設定(最終バックアップ・削除後保持)を実機で確かめる。手順書の「残っている」は設定値で裏を取る(fukuro-automations 2026-10-25)
