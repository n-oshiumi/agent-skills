# test — テスト設計・品質ゲート・E2E

## 何をテストするか
- [P1] 触ったコードパスを異常系・境界値(空・null・権限なし・タイムアウト・API 失敗)まで網羅する。バグ修正は回帰テスト必須(修正前に失敗 → 修正後に通ることを確認)
- [P1] 検証ルールは拒否パスで確認する(happy path のみ禁止)。認可に触れる変更は全ロール+所属外の拒否パスまで網羅し、負のパスを skip で放置しない
- [P1] スコープ分離・制約・権限は実 DB の統合テストで押さえる(全面 mock のユニットだけで済ませない)。新しいスコープ付きアクセサにクロススコープ否定テスト
- [P1] 特権/破壊的処理のテストは「拒否する」だけでなく「副作用ゼロ」も assert する。対称な状態遷移ガードは両方向の否定テストを対で置く
- [P1] 暗黙の自動処理(フック・オブザーバ・トリガ)の副作用を変えたら副作用そのものをテストで明示確認する。削除系の関連データの残る/消える仕様をテストで確定する
- [P1] 外部サービスからの受信(webhook)に、署名成功・署名不正/欠落・未知イベント・主要イベントごとの副作用のテストがある
- [P1] 例外ハンドラ/ミドルウェアの応答を変えたら文言そのものを assert し、HTTP 層を通る経路でテストする(例外を直接 new するユニットだけで結論しない)
- [P1] 事故の再発を防ぐ「配線の 1 行」にテストがある。配線は「呼ばれた」だけでなく「どこへ・何を」まで assert し、純関数のテストと配線のテストを別々に固定する
- [P1] 純関数へ切り出したら呼び出し側の結線とエントリの分岐もテストで固定する。新しく export した関数を同ファイルの別関数のテストで「テスト済み」と見なさない
- [P1] 関数に外部呼び出しを足したら、その関数のテストの mock 一覧も見る。注入したテストダブルと本番アダプタの契約を突き合わせる
- [P2] UI の微調整・スタイル変更・副作用中心コードはテスト必須対象外とし、最低限の手動確認手順を示す

## テストが本当に効いているか
- [P1] ガードを足したら、そのガードだけを外す変異で当該テストだけが落ちることを実測する。テストの存在は保護の証明にならない
- [P1] 「存在」でなく「値」を固定する(定数の存在だけをテストしない、挙動を n / n+1 で固定)。部分集合マッチで「全指定」を済ませない。否定テストは拒否だけが持つ値まで固定する
- [P1] 「テストが通った」件数に skip を含めない。前提不成立は失敗させるか skip 件数を可視化する。P0 の統合テストは CI で必ず実行し、skip を禁止するガードテストを置く
- [P1] 走査型の静的ガードは走査 0 件で通らない形にする(期待一覧との完全一致か件数下限)。検査ヘルパが 0 件を黙って通さない
- [P1] 機械ゲート(guard test / lint / hook)にネガティブケースを付け、本体と同じ関数を通す(正規表現をコピーして持つと片方だけ直した瞬間に担保が名目になる)
- [P1] 壊れた挙動を期待値としてテストに固定していないか。修正の検証を negative assert だけで済ませない
- [P1] テスト名が主張する内容を render/実行範囲で検証できているか。部分一致で UI の存在を確かめない。テスト名は実装の条件式の写しでなく仕様の言葉で
- [P1] 新しいテストの置き場がランナーの include にマッチするか。ゲート出力のテストファイル数・件数を読む
- [P1] 定数リストからテストを生成したら、リスト自体が縮んでいないことを別に固定する
- [P2] fixture は同型の別フィールドに異なる値を入れる。比較先を粗い整形関数に通さない。テスト用スタブに実コンポーネントには無い属性を生やしてセレクタに使わない

## テストの衛生
- [P1] テストデータ生成を現在時刻に依存させない。表示整形の環境依存(TZ・ロケール)を固定し、時刻の一致テストに月初 00:00 と年跨ぎを含める
- [P1] 共有状態を残すテストの担保は「後始末」ではなく「開始前の作り直し」。共通 fixture に置き、逸脱は機械ゲートで検出する
- [P1] テストが引数を省略して本番の秘密保管庫・本番 API・実在ファイルに落ちない。統合テストはテスト専用 DB で。一時ファイルは他テストの走査ルート外に置く
- [P1] 外部依存(LLM・DB・ストレージ)は実 API に当てず mock し、失敗・タイムアウト・rate limit も mock する
- [P2] 描画ライブラリの mount を単体テストに含めない(純関数と表示コンポーネントに分割)
- [P2] 生成 AI の出力を検証する正規表現は、AI が実際に書いた本文を fixture に固定する

## 実測・ゲート
- [P1] 「品質ゲート通過」と書く前に正本のコマンドをそのまま実行し、終了コードで読む(tail や部分実行で代用しない)。赤いテストを「本差分起因でない」で据え置かない。恒常赤のゲートはゲートでない
- [P1] base を取り込んでからゲートを回す(逆順だと分岐時点の古いガードに対して緑になる)
- [P1] 新しく足したチェック・分岐が「1 件も走っていない」まま OK 判定されていないか。件数を数字で確認し、0 件なら「対象に到達していない」を先に疑う
- [P1] 「該当データがなかったので未検証」を未検証のまま通さない。該当ゼロを証明するか、到達不能をコードで示す
- [P1] 生成物は「成功したか」でなく出力そのもの(実寸・実形式・中身が読めるか)で検算する。実データの DRY_RUN 成果物を実際に開いて読むまで配信しない
- [P1] 一括編集後は全ファイルに構文検査・未定義参照検査を掛ける(テストが通ることは変更ファイルが壊れていないことを意味しない)
- [P1] ローカルサーバへの確認は、そのサーバが自分のビルドだと確かめてから(同ポートに別セッションのサーバが居ると全 PASS する)。新規経路の 200 を既存経路より先に確認する
- [P1] 指摘に沿って直したら、指摘の再現手順をそのまま当て直す。検証したあとに修正したら再検証する

## E2E
- [P1] E2E は網羅しない。網羅はユニット・結合テストの責務で、E2E を厚くすると flaky になる。「壊れたら売上が止まる / 事故になる」経路だけを置く
- [P1] 本番に対しては読み取り専用の疎通確認のみ。決済導線はローカル+テスト鍵で、外部決済ページへ向かうところで止める
- [P1] E2E が落ちたら「自分の変更が壊した」と読まず、土台(テストデータ・キャッシュ・スキーマ・環境変数)を先に切り分ける。単体実行で通る/フルスイートで落ちる、を確認する
- [P1] 状態を消費するテスト(予約・在庫)は実行前に状態をリセットし、テストデータは種類ごとに複数件持たせる。キャッシュ状態を別環境から持ち込まない
- [P1] チェックリストの経路がスクリプトに実装されているか照合する(指定した経路が黙って未実行になると通過に見える)
- [P1] 導線の判定は文言でなく遷移先で行う。検査に使う値(価格・閾値)は正本の定数から引き、検査に書き写さない
- [P1] 判定は必須経路の全 PASS + 変更が触った差分経路の PASS。未検証を FAIL=0 に読み替えて通過にしない。閾値が落ちたら何が押し下げたかを測ってから見直しを合意する(黙って緩めない)
- [P1] 視覚的欠落(折返し・オーバーフロー)は DOM 存在チェックでは検出できない。実ブラウザの boundingBox / isVisible で判定する
- [P2] 読み込みタイミング起因の非決定的失敗は待ち条件を強めた上で 1 回だけ再測。2 回続けて落ちたらアプリを疑う
