# common — 全レイヤー共通(常に読む)

## 仕様・完全性
- [P0] 仕様どおりか(正常系・エッジ・エラー・空状態)。不明な要件は推測で埋めず確認する
- [P0] 端から端まで完成しているか(利用者側に加え管理側の作成/編集/削除まで)
- [P0] 実装前に関連 spec / ADR の「決定」節と突合する。判断を変えたら同じ差分で spec を書き戻す
- [P1] 呼び出し先が実在し、引数が本番経路で実際に渡るか。新しい関数・ジョブ・イベントの呼び出し元/購読者を grep する(定義は配線の証明でない)
- [P1] 人の承認を後段の無人処理の認可にするなら、無人側の機械検査を承認時点でも走らせて見せる(分かれると承認済みが黙って止まる)
- [P2] 仕様の挙動(拒否せず警告等)を外部ライブラリに任せるなら、その既定が先に拒否していないか実装を読む

## 入力と境界
- [P0] 外部入力(リクエスト・webhook・CLI 引数・ファイル名)は境界で形式と実在性まで検証し、手入力の識別子で引いた外部リソースが意図した対象か確かめる
- [P0] 識別子・外部入力をパス・キー・シェル・生 SQL・HTML に埋める直前に検証/エスケープする(自前 DB 由来でも。LLM の生成値は書く前に文字種を許可リストで絞る)。エスケープは出力時に 1 回
- [P0] 許可リストを「`/` を含むか」(素の `.env.x` が通る)や `^...$`(PHP・Python・Ruby の `$` は末尾改行を通す)で判定しない。接頭辞で照合して `\z`・`fullmatch` で閉じ、否定テストに素の名前と末尾改行付きの値を入れる
- [P0] 一括操作(承認・配信・削除)の対象はサーバで単発経路と同じ除外条件にし、書き込み直前に読み直して絞る(位置でなく内容で照合)。確認文言の件数は重複を除いた実行件数
- [P1] 照合・fail-closed 判定を短い識別子・部分一致・表示名(分類名・ディレクトリ名)で書かない(改名で黙って 0 件・同名を誤検出)。種別コードか中の設定で判定し、対応付けできないものは「未検査」と出す。外部文字列の短い語は単語境界で閉じる(`tel` が Hotel に当たる)。ログを除外して数える監視も行頭で固定する(送り手の値入りの行で検知を消せる)
- [P1] 甘くする向きの分類(除外・スキップ)は取りこぼしと誤検知のどちらが安全側か先に決める。止める向きの手掛かりは 1 つ当たれば優先する
- [P1] 同一性判定・ハッシュ・ロックのキーは正規化後の値で。表示名から派生する一意 ID は派生後の値で生成時に重複判定する
- [P1] 検出ルールの誤検知を潰したら真陽性がまだ当たるか実入力で確かめる。文の検査は固有名詞を除いて掛ける
- [P1] 文字種で拒否する規則は、trim で落ちない不可視文字(U+3164・U+2800)と実名に要る例外(異体字セレクタ・結合文字)を否定・肯定の両テストに入れ、DB に写すなら全コードポイントで一致させる

## 欠損・既定値・判定の向き
- [P1] 空・未指定・読めない・0・判定不能を区別し、倒れる向きを明示する(`?? 0` が満点・0件・OK に倒れないか)。例外・空を返したときの呼び出し側を追う。最後の絞り込みが空なら先頭候補へ戻さず「一致なし」で止める
- [P1] 成功応答に期待フィールドが無いのを「正常な 0 件」にしない。渡していない任意パラメータの既定値を見る。「失敗なら X が返る」前提はその条件を確かめる(一括 API は一部失敗が成功に見える)
- [P1] 合否を決める率は仕様の群ごとの分母で計算し、判定器の版を集計キーに入れる。多条件の探索結果を後段で差し替えず、フィルタは探索ループに入れる

## 重複と横展開
- [P1] 同じ判定・変換・定数・数え方を 2 箇所に書かず正本 1 つを参照する。共有の定数・閾値を変えたら読む全モジュールを grep して同じ差分で直す
- [P1] 列挙値・役割・語彙を足したら、全層(保存→クエリ→型→文言→switch)を grep して揃える
- [P1] 同型のバグは横展開し、置き換えた識別子・文言は古い形が 0 件かを grep する。削除の残骸も同じ差分で処理する
- [P1] doc コメントの不変条件・指標定義(基準日・分母)を破るなら、その更新も同じ差分で行う

## エラーハンドリング
- [P1] 3 分類で見る: A. 未処理 / B. 伝えない(ログのみ・空 catch・state 未反映) / C. 不適切な表示(技術詳細・例外原文・次の行動が不明・機密)
- [P1] 分類コードに丸めても原因の手掛かりを残す(1 コード 1 原因)。原因(一時障害/権限/対象なし/自分で止めた)ごとに文言と行動を分ける
- [P1] 包括 catch が配線ミスまで飲み込まないか。付加情報・操作後の記録や計測の失敗を本体の失敗・見送りに昇格させない
- [P2] ガードの作動は run サマリ・カウンタに出す。常時作動する正常系を外すなら同じ見た目の異常系が別経路で見えるか

## 子プロセス・外部コマンド・生成物
- [P1] 外部コマンドの成否を終了コードだけで決めず、副作用の完了を出力・照会で確かめて記録する。子プロセスの結果ファイルで合否を決めるなら今回書かれたことを時刻か実行 ID で確かめる
- [P1] `stdio: pipe` のストリームは最後まで読むか `ignore` にする(埋まると子が止まる)。記録は閉じるのを待ち、書き込み失敗は完了通知の引数でも見る(成功終了に化ける)。可変長オプションの後ろに位置引数を置かない
- [P1] `claude --print` の出力を機械解析するなら `--settings '{"disableAllHooks":true,"outputStyle":"default"}'` で hook・出力スタイルを切る
- [P1] 別工程が上書きする成果物を別用途に流用しない(出力パスに対象名を含める)。版の指紋に毎回書き直すファイルを含めない
- [P1] 取り直すキャッシュ・参照データは、失敗時に完全な既存版を上書きせず終了コードで返す(不完全版で下流のゲートが一斉に落ちる)
- [P1] 動作確認で起動したプロセスは控えた PID だけで止める(`pkill -f`・ポート指定の kill は他を巻き込む)
- [P2] フォーマッタは編集したファイルだけに当てる

## LLM の判定
- [P1] 判定出力を合否に使うなら全件判定・重複なし・候補外なしを検査し、崩れたら不合格に倒す。1 回で決めず(同じ入力でも合否が入れ替わる)、不合格は記録し再検査で黙って通さない

## 秘密・機微情報
- [P0] 秘密(鍵・トークン・認証なしの URL)をコード・ログ・例外・URL クエリ・コマンド引数・コミットに載せない。環境変数の全継承で子プロセスへ渡らないか
- [P0] 機微情報は「値」「文言(分岐に入った事実)」「文脈」の 3 層で見る。件数・バケットが機微属性に 1:1 対応しないか
- [P0] 無人エージェントが書ける場所のファイルをランナーが source・実行・設定として読まない
- [P1] 鍵を伏せても例外文には上流の本文断片が残る。通知・ログには種別(status・接続失敗・鍵なし・Content-Type・長さ)だけ載せる
- [P1] 鍵を新規発行させる前に発行上限・再発行で既存が失効する条件を確かめる。不明なら既存を共用し停止は失効以外で持つ
- [P1] 重要な管理操作(権限変更・削除・課金・公開)に監査ログ(誰が・いつ・何を)を残す

## 時間・並行・上限
- [P1] 自動ループに上限回数・連続失敗の打ち切り・人が止める手段、殺されうる処理に殺されたときの経路(状態確定・stale 判定)があるか
- [P1] 検査と処理の対象が同じか(取ってから検査→取り直して処理は TOCTOU)
- [P1] 閾値は 1 つに 1 役割。率の判定には小分母の下限を置く。決定論的に同じ結果になる失敗は再試行しない
- [P1] 締切が複数あるなら止めた理由は「単独でも止めるもの」で決める。判定を次の実行に委ねるなら次の実行が締切前に来るか
- [P2] 待ち時間(now + 残り)を表示するなら終了時刻が停止帯・締切をまたがないか
- [P1] 非同期の二重完了・購読/タイマーの解放漏れ。TZ は 1 つに決め、業務上の順序は時刻でなく単調採番で
- [P1] ロックは原子的に取り、pid で持ち主を判定するなら起動時刻も照合する(使い回しを生存と誤る)。古いロックは 1 本ずつ引き継いで持ち主を再確認し、取得途中の中断で残らないか見る

## 取り消せない操作
- [P0] 実行済み記録をファイルで持つなら消失・切り詰め・不正値が「未実行」に倒れないか(前回の件数・時刻を別に残す)
- [P1] 複数ステップの外部書き込みは途中失敗の後始末を持つ。破壊的・上書き操作は確認を取り、戻れないなら仕様と確認文言に明記する

## コード衛生
- [P1] マージ済みの類似実装と命名・構成を揃える(独自の改良より既存の型)
- [P2] 不要コード(旧関数・未使用 import・コメントアウト・デバッグ出力)を消す。認可の甘い旧ルートが残るなら P1
- [P2] マジックナンバーの定数化。コメントは Why not だけ(処理の要約・手順番号・言い換えを書かない)
- [P2] 生成物を手で編集せず正本側を直す。スキーマ / API 契約を変えたらドキュメントを更新する
