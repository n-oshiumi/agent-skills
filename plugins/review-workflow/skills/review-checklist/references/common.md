# common — 全レイヤー共通(常に読む)

## 仕様・完全性
- [P0] 仕様どおりか(正常系・エッジ・エラー・空状態)。不明な要件は推測で埋めず確認する
- [P0] 端から端まで完成しているか(利用者側だけでなく管理側の作成/編集/削除まで)
- [P0] 実装前に関連 spec / ADR の「決定」節と突合したか。判断を変えたら同じ差分で spec を書き戻す
- [P1] 呼び出し先が実在し、引数が本番経路で実際に渡るか。新しい関数・ジョブ・イベントの呼び出し元/購読者を grep する(定義は配線の証明にならない)
- [P1] 人の承認を後段の無人処理の認可にするなら、無人側が止める機械検査を承認時点でも走らせて見せる(分かれると承認済みが黙って止まる)
- [P2] 仕様の挙動(拒否せず警告等)を外部ライブラリに任せるなら、ライブラリの既定が先に拒否していないか実装を読む

## 入力と境界
- [P0] 外部入力(リクエスト・webhook・CLI 引数・ファイル名)は境界で形式と実在性まで検証する。手入力の識別子で引いた外部リソースが意図した対象か確かめる
- [P0] 識別子・外部入力をパス・キー・シェル・生 SQL・HTML に埋める直前に検証/エスケープする(自前 DB 由来でも。LLM の生成値は設定・台帳に書く前に文字種を許可リストで絞る)。エスケープは出力時に 1 回
- [P0] 許可リストの判定を「`/` を含むか」(素の `.env.x` が素通る)や `^...$`(PHP・Python・Ruby の `$` は末尾の改行を通す)で書かない。接頭辞で照合して `\z`・`fullmatch` で閉じ、否定テストに素の名前と末尾改行付きの値を入れる
- [P0] 一括操作(承認・配信・削除)の対象はサーバで単発経路と同じ除外条件で、書き込み直前の読み直しで絞り直す(読み戻しは位置でなく内容で照合)。確認文言の件数は重複を除いた実行件数
- [P1] 照合・fail-closed 判定を短い識別子・部分一致・表示用の名前(分類名・ディレクトリ名)で書かない(名前が変わると黙って 0 件・同名を誤検出)。種別コードや中の設定で判定し、対応付けできないものは外さず「未検査」と出す。甘くする向きの分類(除外・スキップ)は取りこぼしと誤検知のどちらが安全側か先に決める
- [P1] 同一性判定・ハッシュ・ロックのキーは正規化後の値で。表示名から派生させる一意 ID の重複判定は派生後の値で生成時に行う
- [P1] 検出ルールの誤検知を潰したら真陽性が今も検出されるか実入力で確かめる。文の検査は固有名詞を除いた本文に掛ける

## 欠損・既定値・判定の向き
- [P1] 空・未指定・読めない・0・判定不能を区別し、倒れる向きを明示する(`?? 0` 等の既定値が満点・0件・OK に倒れないか)。例外・空を返したときの呼び出し側を経路で追う。最後の絞り込みが空なら先頭候補へ戻さず「一致なし」で止める
- [P1] 成功応答に期待フィールドが無いのを「正常な 0 件」にしない。渡していない任意パラメータの既定値を確認する。「失敗なら X が返る」前提の分岐は X が返る条件を確認する(一括 API は一部失敗が成功に見える)
- [P1] 合否を決める率は仕様が定めた群ごとの分母で計算し、判定器の版を集計キーに入れる。多条件の探索結果を後段のフィルタで差し替えず、フィルタは探索ループに入れる

## 重複と横展開
- [P1] 同じ判定・変換・定数・数え方を 2 箇所に書かず、正本 1 つを全経路から参照する。共有の定数・閾値を変えたら、読む全モジュールを grep して同じ差分で直す
- [P1] 列挙値・役割・語彙を足したら、全層(保存→クエリ→型→文言→switch)を grep して同時に足す
- [P1] 同型のバグは横展開し、置き換えた識別子・文言は「古い形が 0 件」を grep で確かめる。削除の残骸も同じ差分で処理する
- [P1] doc コメントの不変条件や指標定義(基準日・分母)を破る変更は、その更新も同じ差分に含める

## エラーハンドリング
- [P1] 3 分類で見る: A. 未処理 / B. 伝えない(ログのみ・空 catch・state 未反映。再確認手段か画面表示が要る) / C. 不適切な表示(技術詳細・例外原文・次の行動が不明・機密)
- [P1] 分類コードに丸めても原因の手掛かりを残す(1 コード 1 原因)。原因種別(一時障害/権限/対象なし/自分で止めた)ごとに文言と行動を分ける
- [P1] 包括 catch が配線ミスまで飲み込まないか。任意の付加情報・操作後の記録や計測の失敗を、本体の失敗・見送りに昇格させない
- [P2] ガードの作動は run サマリ・カウンタにも出す。常時作動する正常系を外すなら、同じ見た目の異常系が別経路で見えるか

## 子プロセス・外部コマンド・生成物
- [P1] 外部コマンドの成否を終了コードだけで決めない。副作用の完了は出力・照会で確かめ、記録はその事実に従う。子プロセスが書く結果ファイルで合否を決めるなら、今回の実行で書かれたことを時刻か実行 ID で確かめる
- [P1] `stdio: pipe` のストリームは最後まで読むか `ignore` にする(バッファが埋まると子が止まる)。出力の記録は閉じるのを待ち、書き込み失敗は完了通知の引数でも見る(成功終了に化ける)。可変長オプションの後ろに位置引数を置かない
- [P1] `claude --print` の出力を機械解析するなら `--settings '{"disableAllHooks":true,"outputStyle":"default"}'` で利用者の hook・出力スタイルを切る
- [P1] 別工程が上書きする成果物を別用途の入力に流用しない(出力パスに対象名を含める)。版の指紋に毎回書き直すファイルを含めない
- [P1] 外部から取り直すキャッシュ・参照データは、取り直しの失敗で完全な既存版を上書きしない(不完全版が下流のゲートを一斉に落とす)。失敗は終了コードで返す
- [P1] 動作確認で起動したプロセスは控えた PID だけで止める(`pkill -f`・ポートからの kill は他のプロセスを巻き込む)
- [P2] フォーマッタは編集したファイルだけを名指しで当て、`git add <path>` でコミットする

## LLM・モデルの判定
- [P1] 判定出力を合否に使うなら全件判定・重複なし・候補外なしを検査し、崩れたら不合格に倒す。1 回の判定で決めない(同じ入力でも合否が入れ替わる)。不合格を記録して再検査で黙って通さない

## 秘密・機微情報
- [P0] 秘密(鍵・トークン・認証なしの URL)をコード・ログ・例外・URL クエリ・コマンド引数・コミットに載せない。子プロセスへ環境変数の全継承で渡らないか
- [P0] 機微情報は「値」「文言(分岐に入った事実)」「文脈」の 3 層で見る。件数・バケットが機微属性に 1:1 対応しないか
- [P0] 無人エージェントが書ける場所のファイルを、ランナーが source・実行・設定として読まない(置き場を書けない場所へ移す)
- [P1] 鍵を伏せても例外文には上流の本文断片が残る。通知・ログには種別(status・接続失敗・鍵なし。応答が読めないなら Content-Type・長さ・壊れ方)だけを載せる
- [P1] 鍵を新規発行させる前に発行上限・再発行で既存が失効する条件を確かめる。不明なら既存を共用し、停止は失効以外で持つ
- [P1] 重要な管理操作(権限変更・削除・課金・公開)に監査ログ(誰が・いつ・何を)を残す

## 時間・並行・上限
- [P1] 自動ループに上限回数・連続失敗の打ち切り・人が止める手段があるか。殺されうる処理に殺されたときの経路(状態確定・stale 判定)があるか
- [P1] 検査と処理の対象が同じか(取ってから検査→取り直して処理は TOCTOU)
- [P1] 閾値は 1 つに 1 役割。率の判定には小分母の下限を置く。壊れ方が決定論的かランダムかを確かめ、同じ結果になる失敗は再試行しない
- [P1] 締切が複数あるなら止めた理由は「単独でも止めるもの」で決める。判定を次の実行に委ねるなら、次の実行が締切前に来るか確かめる
- [P2] 待ち時間(now + 残り)を表示するなら、終了時刻が停止帯・締切をまたがないか確かめる
- [P1] 非同期の二重完了・購読/タイマーの解放漏れ。TZ は 1 つに決め、業務上の順序は時刻でなく単調採番で決める

## 取り消せない操作
- [P0] 実行済み記録をファイルで持つなら、消失・切り詰め・不正値が「未実行」に倒れないか(前回の件数・時刻を別に残す)
- [P1] 複数ステップの外部書き込みは途中失敗の後始末を持つ
- [P1] 破壊的・上書き操作は確認を取る。戻り経路が無ければ仕様と確認文言に明記する

## コード衛生
- [P1] マージ済みの類似実装と命名・構成を揃える(独自の改良より既存パターン)
- [P2] 不要コード(旧関数・未使用 import・コメントアウト・デバッグ出力)を削除する。認可の甘い旧ルートが残るなら P1
- [P2] マジックナンバーの定数化。コメントは Why not だけ(処理の要約・手順番号・言い換えは書かない)
- [P2] 生成物を手で編集せず正本側を直す。スキーマ / API 契約を変えたらドキュメントを更新する
