# backend — API・サービス層・ジョブ・認可・外部連携

## 認証・認可
- [P0] エンドポイント/アクションごとにサーバ側で認証を検証する。「ミドルウェアで守られている」を理由にしない。外部 callback(webhook)を認証ゲートが塞いでいないかも見る
- [P0] 認可はリソース単位で行い、取得/更新/削除のクエリ条件に所有者・テナント識別子を含める(管理操作の対象 ID も自スコープに再スコープする: IDOR)。テナントはクライアント入力でなくサーバ側セッションから確定する
- [P0] 一覧の権限・表示条件が個別取得より緩くない。「この状態は見せない」は一覧だけでなく個別取得・更新でも 404 に倒す。更新可否は更新後の値で判定する
- [P0] 永続化層へ渡す値は検証済みのものだけ。生のリクエスト全体を流すと主キー・所有者 ID を注入される(mass assignment)
- [P1] フィーチャーフラグ・クライアントの分岐・UI で隠したことをアクセス制御にしない。状態ゲート(要パスワード変更・セッション失効)もサーバ側で強制する
- [P1] 状態変更リクエストに CSRF 対策、生成系・高コストのエンドポイントにレート制限がある。第三者へ届く送信(確認メール・招待)の回数制限は正規化した宛先をキーにし(利用者 ID 単位は作り直しで外れる)、未送信が確定した失敗では自分の確保だけ外す
- [P1] 管理操作の対象が実行者自身のとき資格情報を壊さない。権限主体を 0 人にする操作を止める
- [P1] ログイン識別子が変更可能な値なら、確認系トークンは発行時の不変 ID と照合する
- [P0] 外部 API の必要スコープは呼ぶメソッドごとに確認する(不足は「同意は通るが後段だけ 403」で出る)
- [P0] 利用者ごとの GET に CDN・ゲートウェイの応答キャッシュを効かせるなら、キャッシュキーに認証情報を含める(他人の応答が返る)

## 入出力
- [P0] 金額・通貨・商品はサーバ側で決定し、通貨は最小単位の整数で扱う
- [P1] レスポンスは整形層を通し、隠すべきフィールド・外部 API の生レスポンス・閾値や判定ロジックをクライアントへ渡さない(サーバが確定値・絶対時刻を返す)
- [P1] エラー応答の body 形とステータスを全経路で統一する(エラー時に 200 を返さない)
- [P1] クライアントが叩くパス・キーがサーバ定義と綴りまで一致するか相手側を読む。API 契約の変更で旧クライアントを壊さない
- [P1] 受信スキーマの表示目的の任意フィールドは局所的に縮退させ、型不一致で全体の parse を落とさない。書き込み検証は変更したフィールドだけに掛ける(古い既存値が他の更新まで止める)。必須チェックを「別経路で揃う」と緩めるなら、その経路が使われる条件と同じ条件で緩める
- [P1] 機械判定をメッセージ文字列の一致で書かない。判定に使う事実はコード・定数として戻り値に持たせる

## 状態遷移・トランザクション・冪等性
- [P0] 状態遷移と楽観ロックは条件付き UPDATE + 影響行数で原子的に行う(「読む→比較→書く」はトランザクション内でも壊れる)。ロックは必ず存在する親行で取り、「有効行を失効 → 新行を確定」はロック後に確定対象が未確定か再検証する。運用 CLI 経路にも同じ不変条件を掛ける
- [P1] 版を足したら、版が守る列を更新する全経路(FK カスケードで間接的に変わる列を含む)で版を進める。内容が変わらない書き込みでは版を進めない
- [P0] 複数テーブル更新はトランザクションで包み、同時実行があり得る処理は行ロックを取る。トランザクション内で副作用(通知)を発火しない
- [P0] 再実行・再配信され得る処理は冪等(at-least-once は完了後も再配信される。排他では防げない。外部サービスの重複排除でも代わりにならない)。差分加算はイベント ID ベースで処理済み記録と同一トランザクションに入れ、実数から再集計できる経路を持つ。冪等性キーは検証済みのクライアント入力だけから計算する(サーバ導出値・時刻を混ぜない)
- [P0] webhook は生ボディで署名検証し、重複・順序不定・並行配信で壊れない。進行中はスキップし再試行は終端状態に限る。処理中に外部 API の応答を待たせない。「処理済み」の印を内容ハッシュで表さない(ABA)。更新 WHERE は到達し得る全状態を含め、dead-letter を別経路が巻き戻さない
- [P0] 一括 upsert にまとめるときは入力内の同一衝突キーを畳む(処理ごと落ちる)
- [P1] キュー本文はシリアライズ後(エスケープ込み)の大きさで上限と比べる。outbox の一括送信は宛先・権限を 1 件ごとに送る直前で引き直し、行 ID を冪等キーとして渡す
- [P1] lease は所有トークンで fencing し、TTL が処理時間より長いか heartbeat で延長する
- [P1] 絞り込み条件は全経路に掛ける: 収集と更新が分かれるなら更新の WHERE に収集条件をすべて書き、検索条件は一覧と件数集計の両方に適用する。監査ログは実際に更新した行から書く(件数は行の集合ではない)
- [P1] 「予約 → 外部 API → 反映」で予約と完了を同じ値で表さない。完了の証拠(外部リソース ID)で区別し、予約に失効期限を置く
- [P1] 参照系ハンドラに書き込みを足さない。足すなら単一クエリ・副作用なし・巻き戻らなくても破綻しない形にする

## 外部 I/O
- [P1] 外部 API・ファイル I/O の失敗を捕捉し応答に変換する(タイムアウトと try は本文読み取りまで含め、規模の違う対象に同じ上限を当てない)。一時エラー(5xx・429・接続断)だけ指数バックオフで再試行し、401/403/404 は即失敗。拒否されたら同じ間隔で再試行しない
- [P1] 成功を HTTP ステータスだけで判断しない。ボディの成否・次に渡す ID を取り消せない操作の前に検証し、送信ヘルパーは返り値を見てから送信済みを確定する
- [P1] 外部の設定・ページを読み取って判断する機能は実データを 1 件見るまで完成扱いにしない。「見つからない」と「確定できない」を分け、読み込みに依存する属性(遅延画像の URL)だけで識別しない。クローラは実サーバの挙動差(HEAD 拒否等)を見込む
- [P0] 書き込みリクエストの形(パラメータ名・型・必須)はモックのテストで保証されない。実 API に一度通すまで未検証とし、通したら送信内容を完全一致で固定する
- [P1] SSRF: ユーザー指定 URL は DNS/IP 検証・リダイレクト手動処理・プライベート IP 遮断の共通経路のみ。オープンリダイレクト・パストラバーサル・LIKE エスケープ漏れ・raw 出力への未エスケープ連結がない
- [P1] アップロードは MIME/拡張子/サイズを検証し(悪性 SVG/HTML を画像として受けない)、保存パスに所有者識別子を含め、非公開データは短寿命の署名付き URL で返す
- [P1] LLM: ユーザー入力をシステムプロンプトに混ぜない、出力はランタイム検証、コスト上限、ストリーミングの中断・終了後の状態確定

## パフォーマンス・キャッシュ
- [P1] N+1・全件取得がない。独立した取得は並列化し、並列数が接続プール上限に近いなら取得・文タイムアウトを置く(無いと無限待ちが後続を巻き込む)
- [P1] キャッシュ元を更新・削除したら同じキーを破棄する。テナント別データを共有キャッシュしない。鮮度が要る判定はキャッシュ・非同期の派生値でなく、判断する transaction で正本から計算する
- [P1] 突き合わせる複数クエリは同一スナップショットで読み、「最初の行」を採る集計に ORDER BY を付ける
- [P1] 非同期の通知/ジョブはリクエストコンテキストを参照せず、生成時に受け渡す

## 定期ジョブ・無人処理
- [P1] 「成功」をサマリの status で判定しない(早期 return も ok を返す)。前進を示す信号と利用者に見える状態で判定し、「処理対象 0 件」を検知する
- [P1] 再実行が収束する(定義の再適用 upsert も含め進捗を巻き戻さない)。前段がスキップされた経路が後段を無条件に呼ばない。「やることが無ければ終了」ゲートが新規対象を弾かない
- [P1] 走行中の処理への相乗りも共有資源(外部 API の発行枠・ロック・DB 接続)を奪い合う。消費する主体を数える
- [P1] 監視・移行の対象境界は暦日でなくデプロイ時刻にする

## 候補(レビューで発見)
- [P1] 全員宛ての「確定」通知は、確定条件を下流の集計と同じ有効判定で書き、「送らない」条件は分かった時点で記録し、時間帯の抑止は送信直前の時刻で確かめる(love_trinita 順位確定通知)
- [P2] AES-GCM の復号は `authTagLength` を固定するかタグ長を確かめる。保存したタグをそのまま `setAuthTag` に渡すと短いタグが通り改ざん検出が弱まる(clinic-dashboard envelope.ts)
