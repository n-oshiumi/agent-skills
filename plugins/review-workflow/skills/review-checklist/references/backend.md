# backend — API・サービス層・ジョブ・認可・外部連携

## 認証・認可
- [P0] エンドポイント/アクションごとにサーバ側で認証を検証する。「ミドルウェアで守られている」を理由にしない。外部 callback(webhook)を認証ゲートが塞いでいないかも見る
- [P0] 認可はリソース単位で行い、取得/更新/削除のクエリ条件に所有者・テナント識別子を含める。テナントはクライアント入力でなくサーバ側セッションから確定する
- [P0] 管理操作の対象 ID は必ず自スコープに再スコープする(IDOR)。UI で隠した操作もサーバ側で再チェックする
- [P0] 一覧の権限・表示条件が個別取得より緩くない。「この状態は見せない」は一覧だけでなく個別取得・更新でも 404 に倒す。更新可否は更新後の値で判定する
- [P0] 永続化層へ渡す値は検証済みのものだけ。生のリクエスト全体を流すと主キー・所有者 ID を注入される(mass assignment)
- [P1] フィーチャーフラグ・クライアントの分岐をアクセス制御に使わない。状態ゲート(要パスワード変更・セッション失効)もサーバ側で強制する
- [P1] 状態変更リクエストに CSRF 対策、生成系・高コストのエンドポイントにレート制限がある
- [P1] 管理操作の対象が実行者自身のとき資格情報を壊さない。権限主体が 0 人になる操作を止める
- [P0] 外部 API の必要スコープは呼ぶメソッドごとに確認する。不足は「同意は通るが後段だけ 403」で出て再認証でも直らない。強い権限が要るなら先にその操作をやめる設計を検討する

## 入出力
- [P0] 金額・通貨・商品はサーバ側で決定し、通貨は最小単位の整数で扱う
- [P1] 外部入力を境界でスキーマ検証してから使う。検証エラーの既定メッセージをそのまま返さない
- [P1] レスポンスは整形層を通し、隠すべきフィールドを漏らさない。外部 API の生レスポンスをクライアントへ渡さない
- [P1] エラー応答の body 形とステータスを全経路で統一する(エラー時に 200 を返さない)。例外原文・SQL・スタックを露出しない
- [P1] クライアントが叩くパス・キーがサーバ定義と綴りまで一致するか相手側を読んで確かめる。API 契約の変更で旧クライアントを壊さない
- [P1] クライアントに閾値・判定ロジックを配布しない。サーバが確定値・絶対時刻を返す
- [P1] 受信スキーマの表示目的の任意フィールドは局所的に縮退させ、型不一致で全体の parse を落とさない
- [P1] 機械判定をメッセージ文字列の一致で書かない。判定に使う事実はコード・定数として戻り値に持たせる

## 状態遷移・トランザクション・冪等性
- [P0] 状態遷移と楽観ロックは条件付き UPDATE(版・状態を WHERE に含める)+ 影響行数で原子的に行う。「読む→比較→書く」はトランザクション内でも競合で壊れる。ロックで直列化するなら必ず存在する親行を取る(0 行時の範囲ロックは初回作成同士を直列化しない)。運用 CLI 経路にも同じ不変条件を掛ける
- [P1] 版を足したら、版が守る列を更新する全経路(FK カスケードで間接的に変わる列を含む)で版を進める。内容が変わらない書き込みでは版を進めない
- [P0] 複数テーブル更新はトランザクションで包み、同時実行があり得る処理は行ロックを取る。トランザクション内で副作用(通知)を発火しない
- [P0] 再実行可能な処理は冪等。差分加算はイベント ID ベースで、処理済み記録と同一トランザクションで行い、実数から再集計できる経路を持つ。冪等性キーは検証済みのクライアント入力だけから計算する(サーバ導出値・時刻を混ぜない)
- [P0] webhook は生ボディで署名検証し、重複・順序不定・並行配信で壊れない。進行中はスキップし再試行は終端状態に限る。「処理済み」の印を内容ハッシュで表さない(ABA)
- [P0] 逐次 INSERT を 1 文の一括 upsert にまとめるときは入力内の同一衝突キーを畳む(同じ行を 2 度更新できず処理ごと落ちる)。行は配列で渡しパラメータ上限を避ける
- [P1] 外部サービスの重複排除を自分の冪等性の代わりにしない。「一度だけ送る」は自 DB の条件付き UPDATE で担保する
- [P1] lease は所有トークンで fencing し、TTL が処理時間より長いか heartbeat で延長する
- [P1] 順序不定イベントの更新 WHERE は到達し得る全状態を含め、打ち切り状態(dead-letter)を別経路が巻き戻さない
- [P1] 収集と更新が分かれる処理は、更新の WHERE に収集条件をすべて書き、監査ログは実際に更新した行から書く(件数は行の集合ではない)
- [P1] 「予約 → 外部 API → 反映」で予約と完了を同じ値で表さない。完了の証拠(外部リソース ID)で区別し、予約に失効期限を置く
- [P1] 参照系ハンドラに書き込みを足さない。足すなら単一クエリ・副作用なし・巻き戻らなくても破綻しない形にする

## 外部 I/O
- [P1] 外部 API・ファイル I/O の失敗を捕捉し応答に変換する。一時エラー(5xx・429・接続断)だけ指数バックオフで再試行し、401/403/404 は即失敗。拒否されたら同じ間隔で再試行しない
- [P1] 成功を HTTP ステータスだけで判断しない。ボディの成否・次に渡す ID を、取り消せない操作の前に検証する。結果に畳んで返す送信ヘルパーは返り値を見てから送信済みを確定する
- [P0] 書き込みリクエストの形(パラメータ名・型・必須)はモックのテストで保証されない。実 API に一度通すまで未検証とし、通したら送信内容を完全一致で固定する
- [P1] 応答が読めないときは Content-Type・宣言長と実読長・壊れ方を記録する。パース例外のメッセージをそのまま記録しない(本文抜粋を含むことがある)
- [P1] タイムアウトは本文読み取りにも効かせ専用コードで分類し、規模の違う対象に同じ上限を当てない。webhook 内で外部 API の応答を待たせない
- [P1] SSRF: ユーザー指定 URL は DNS/IP 検証・リダイレクト手動処理・プライベート IP 遮断の共通経路のみ。オープンリダイレクト・パストラバーサル・LIKE エスケープ漏れ・raw 出力への未エスケープ連結がない
- [P1] アップロードは MIME/拡張子/サイズを検証し(悪性 SVG/HTML を画像として受けない)、保存パスに所有者識別子を含め、非公開データは短寿命の署名付き URL で返す
- [P1] LLM: ユーザー入力をシステムプロンプトに混ぜない、出力はランタイム検証、コスト上限、ストリーミングの中断・終了後の状態確定

## パフォーマンス・キャッシュ
- [P1] N+1・全件取得がない。独立した取得は並列化し、並列数が接続プール上限に近いなら取得・文タイムアウトを置く(無いと無限待ちで後続を巻き込む)
- [P1] 一覧・集計クエリは本番相当の行数で実行計画を取り、全件ソート・ディスク溢れを見る。集約内の DISTINCT は全件ソートを強制する(置き換えで NULL の数え方を変えない)。「昨日まで動いた」障害もデータ量比例の経路を先に実測する
- [P1] キャッシュ元を更新・削除したら同じキーを破棄する。テナント別データを共有キャッシュしない。鮮度が要る判定をキャッシュで行わない
- [P1] 検索条件は一覧と件数集計の全経路に適用する。突き合わせる複数クエリは同一スナップショットで読み、「最初の行」を採る集計に ORDER BY を付ける
- [P1] 非同期の通知/ジョブ内でリクエストコンテキストを参照しない。生成時に受け渡す

## 定期ジョブ・無人処理
- [P1] 「成功」を終了コード・サマリの status で判定しない。「やることが無い」早期 return も ok を返すので、前進を示す信号と利用者に見える状態(最終更新・欠測表示)で判定する。「処理対象 0 件」を検知し、アラート指標が常に非ゼロにならないようにする
- [P1] 再実行が収束する(定義の再適用 upsert も含め進捗を巻き戻さない)。前段がスキップされた経路が後段を無条件に呼ばない。「やることが無ければ終了」ゲートが新規対象を弾かない
- [P1] 走行中の処理への相乗りも共有資源(外部 API の発行枠・ロック・DB 接続)を奪い合う。何が消費するかを数える
- [P1] 監視・移行の対象境界は暦日でなくデプロイ時刻にする。新しい監視は投入直後に手で走らせ出力を読む
