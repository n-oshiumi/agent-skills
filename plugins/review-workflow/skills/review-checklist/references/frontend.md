# frontend — 画面・コンポーネント・状態管理

## 状態と非同期
- [P1] loading / error / empty の 3 状態を扱い、loading を empty より先に出す(取得中に「データなし」をフラッシュしない)。多段フェッチは全完了まで loading、error パスでも loading を解除する
- [P1] 通信失敗を捕捉しユーザーに見える形で通知する。空 catch・console のみの無言失敗禁止。ブラウザ標準の alert/confirm/prompt は使わない
- [P1] 送信中はボタンを無効化し、ハンドラ冒頭でも再入ガードを入れる(Enter 送信とクリックの 2 経路があり disabled だけでは二重送信を防げない)。非同期は finally で loading を解除する
- [P1] 同じ state を書き戻す非同期取得が複数走る経路に、古い応答を捨てる順序ガード(連番)を置く。失敗側のリセットにも
- [P1] 非同期待ちの後の UI 操作(状態更新/遷移/ダイアログ)前に画面の生存を確認する。購読・タイマー・DOM 参照は unmount 時に解除する
- [P1] 子コンポーネントが初期描画時にも発火するイベントを、再取得などの副作用へ直結しない。現状態と同値ならスキップする
- [P1] ポーリングは認証系エラー(401/403/404)で即停止し、連続エラー閾値で止め、cleanup(タイマー解除・世代番号)を持つ。失敗時にスロットルを解除して無制限リトライにしない
- [P1] ユーザーが明示的に切り替えた表示状態(フィルタ・タブ)を、遷移で unmount されるローカル state に置かない
- [P1] 処理を丸ごと飛ばす前に、飛ばした分を後で実行する口があるか

## データと表示の整合
- [P1] 画面のフィルタが実際に取得条件へ渡っている(「操作できるが値が変わらない UI」はバグ)。初期表示の集計条件が既定値と一致する。選択肢は実際に操作できる母集団から作る
- [P1] スコープ・状態を名乗る見出し/ラベルは「実際にデータへ適用された状態」から導出する。ラベルの範囲とクエリの範囲を別変数にしない
- [P1] 比較チップ・注記の母集団が直上の数値と一致する。進行中の期間を閉じた期間と比較しない
- [P1] UI の「可否」判定とサーバ側の実行条件が同じ状態集合を指している。表示元を「状態を見る経路」から差し替えるとき状態別の見え方を確認する
- [P1] 欠測を 0 や淡色だけで表さない(行が無い / 値が 0 / 未完了は別物)。同じ欠測が効く全表示経路に届ける
- [P1] 同じ値を描画する全経路(分岐違い・別コンポーネント・メール・印刷)に同じ整形(改行・空白保持・エスケープ)を適用したか
- [P1] サーバとクライアント両方で描く文字列に実行環境で変わる関数(ロケール時刻等)を使わない
- [P1] 「更新しました」「添付しています」等の断言文言は、実際にそれを行った経路にだけ置く
- [P2] 表示粒度を細かくするとき、値を作る経路の精度がその単位を支えているか

## セキュリティ
- [P1] 生 HTML 挿入にユーザー由来・外部由来の入力をサニタイズ無しで渡さない(リッチテキストのペースト経由も)
- [P1] 外部由来の URL を開く前にスキームを検証する。ブラウザ/Renderer 側に特権 API を直接露出せず、プロセス境界を越える入力は受け側で検証する
- [P1] 認証必須データの購読はサインアウトより前に解除し、直後の権限拒否を致命扱いしない
- [P1] 秘匿値をクライアントに持たせない。持たせるなら送信面(計測・ログ・共有キャッシュ・Referrer)を全部塞ぐ

## 操作性・アクセシビリティ
- [P1] 画面から戻れる導線がある(入口ナビが消える画面は行き止まり)。新しい全画面の面はモバイル幅で戻れることを確かめる
- [P1] モーダル: role="dialog"、フォーカストラップ、全ての閉じ方でフォーカスをトリガーへ戻す。Esc/背景クリックで閉じるかは「入力途中を失わせない」要件で決め、閉じない場合も閉じる導線を常時見せる。重なるダイアログの間はトラップを外す
- [P1] 破壊的操作は確認を取る。エラー通知は自動で消えない手段、成功通知は自動で消えてよい
- [P2] フォーム要素に label、アイコンのみボタンに accessible name、キーボード操作可、コントラスト十分、色・記号だけに意味を持たせない。エラーは該当コントロールの近くに出す
- [P2] 端で操作不能にするコントロールに disabled を使わない(フォーカス喪失)。ページに 1 つ置く要素(live region・見出し)を繰り返し部品や条件分岐の内側に置かない
- [P2] モーダルを閉じるときフォームとエラー状態をリセットし、再送信前に既存エラーをクリアする。CRUD 後は再取得して即時反映し、ページ全体のリロードは避ける

## レイアウト・レスポンシブ
- [P1] 画面を追加・変更したらモバイル・タブレット・PC の 3 幅で実測する(横スクロール・折り返し・数字の桁中折れ・長い語の見切れ・テーブル/チャートの代替表示・タップ領域 44px・固定幅の乱用)。モバイル崩れは P1
- [P1] 枠に入るかを文字数で測らない。画面に出る文字は属性・疑似要素・焼き込み画像も数える
- [P1] 「画面に出す」以外の出力面(印刷/PDF・メール HTML・OGP 画像・CSV)を持つ機能はその面で実測する
- [P2] 条件付きで消えるブロックの「消えた状態」の間隔・縦順を確認する。用語・ラベルは用語集と一致させ、色はデザイントークンから引く。z-index は共有定数から導出する
- [P2] サードパーティ CSS を上書きするとき詳細度と読み込み順を確認する

## パフォーマンス
- [P1] 画面限定のコンポーネント・重量ライブラリを初期バンドルに同期登録しない。一覧に重い埋め込みを並べるなら常駐数の上限と解放経路を持つ
- [P2] 不要な再レンダリング(依存配列の誤り・メモ化漏れ)、リストの安定キー、サーバでできる重い処理をクライアントでしない。画像はサイズ・形式を最適化し装飾は遅延読込
- [P2] 性能改善は「変えた」でなく「効いた」を実測する。Web フォントの適用は計算値で確認する(目視では分からない)

## 計測
- [P1] 分析イベントは SDK の型制約に反するパラメータを渡さない(イベントごと欠落する)。共通ラッパー経由で正規化する。表示イベントは初回表示時のみ、滞在時間はフォアグラウンドのみ

## 候補(レビューで発見)
- [P1] AI 由来でない判定を「AI 解析」と表示しない。生値 / 計算値 / 推定値 / AI 生成値を区別して示す(wemiro-technical / wemiro-marketing 2026-09-08)
- [P2] 重要なチャートにはテキスト要約または表の代替を置き、チャートが描画できなくてもページが理解できる(wemiro-marketing 2026-09-08)
