# threat-coverage — 攻撃の種類ごとの対策状況

テンプレ(`template.md`)の行を、各リポで「状態・守っている仕組み・残っている弱点」まで埋めた表にする。
plugin を更新するとテンプレも新しくなるが、各リポの記入済みの表は古いまま残る。そのため、この skill を呼ぶたびに最初に同期する。

## 手順

1. **公開リポでないことを確かめる**: `gh repo view --json visibility -q .visibility` が `PUBLIC` なら書かずに止め、ユーザーに置き場を聞く。
2. **置く / 同期する**(`S` はこの skill のディレクトリ、`F` は `docs/reference/security-threat-coverage.md`):
   - 表が無い: `node $S/scripts/sync.mjs $F --init`
   - ID 列の無い古い表: `node $S/scripts/sync.mjs $F --adopt` を実行し、推定できなかった行に ID を手で入れる。同じ攻撃ならテンプレの ID(同じ ID を2行に振ってよい)、テンプレに無い攻撃なら `local.<英小文字>` にする
   - 差分を見る: `node $S/scripts/sync.mjs $F`(終了コード 2 = 差分あり)。内容を確認したら `--write` で反映する
   - 同期で足された行の状態は `―`(未点検)。「テンプレから消えた行」は自動では消さないので、要るかどうかをユーザーに聞く
3. **点検して埋める**: 足された行と、頼まれた範囲の行を埋める。
   - 状態: ✅ 対策あり / △ 部分的 / ❌ 対策なし / ― 未点検 / 対象外。読んでいない行に ✅ を付けない
   - 守っている仕組みは `file:line` か設定名、残っている弱点は issue 番号で書く。攻撃の手順は書かない
   - `/security-audit` の結果がある場合は、該当する行の状態と弱点に写す
   - 表の列や節の名前はリポに合わせて変えてよい。ID 列だけは消さず、値も変えない
4. **還流**: テンプレに無い種類の攻撃を見つけたら、`local.` の ID で行を足す。足した行は完了報告に「テンプレへの昇格候補」として書く(同期の出力にも出る)。

## テンプレを育てる(保守者)

- `local.` の候補を昇格するときは、リポ固有の名前と弱点を抜いて `template.md` に行を足す。`template-version` を1つ上げ、`CHANGES.md` に追加した ID を書く。
- 分類を見直して ID を変えるときは、`CHANGES.md` に `- vN: rename: old.id -> new.id` と書く。同期のときに記入済みの値が新しい ID へ引き継がれる。ID を消すだけなら書かなくてよい(各リポでは「テンプレから消えた行」として残る)。
- 配信は他の skill と同じく `tools/release.sh`。
- どのリポがどの版を使っているかは vuln-scan の `latest.json` の `.projects["<名前>"].threat` で見る(版だけを載せ、中身は載せない)。
